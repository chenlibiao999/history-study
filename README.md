# 历史学习工作台

这是从首版静态 HTML 拆出的结构化版本。当前重点是把唐朝学习内容变成可追溯、可维护的数据，而不是堆百科文本。

## 文件结构

### 规则文档

- `data/rules.md`: 历史内容、事件、史料、疆域人口和地图的总规则池。
- `data/rules/agent-collaboration.md`: 三角色协作、职责边界、复用策略和验收流程。
- `data/schema.md`: 数据字段、关联关系和结构约束。

- `index.html`: 页面骨架，只保留布局容器。
- `assets/styles.css`: 视觉样式。
- `assets/app.js`: 渲染、搜索、筛选、切换事件、笔记、复习卡片等交互。
- `data/history-data.js`: 历史事件数据。
- `data/tang-emperors.js`: 唐朝帝王谱系索引，覆盖唐朝皇帝和武周阶段。
- `data/schema.md`: 数据字段说明和后续扩展规则。

## 当前能力

- 左侧主导航支持“大事”和“帝王”两种浏览方式。
- 点击时间线事件会切换中间详情和右侧辅助信息。
- 帝王年表中的事件按钮可直接跳到对应大事件。
- 搜索支持事件、人物、地区、概念的简单匹配。
- 时期、地区、主题筛选可用。
- 右侧包含人物、因果链、史料、引用、复习。
- 引用线索默认展示白话释义，古籍链接只作为出处。

## 内容规则

只录大主线和大事件，在精不在多，在准不在错。

事件页中的 `process` 是大事件内部的“小事件”或“经过节点”。它不能只写一句过短提示，必须让初学者读完能理解这个节点为什么重要。

`process[].description` 规则：

- 通常写 1 到 2 句，约 45 到 120 个汉字。
- 讲清楚谁参与、发生了什么、为什么改变局势或推动下一步。
- 不写百科式铺陈，不展开无关支线。
- 优先解释因果和转折，例如权力转移、制度变化、战局变化、财政变化或政权兴亡。
- 信息量太大时拆成多个 `process` 节点。

## 来源原则

来源优先级：

1. 公开古籍文本，如《资治通鉴》、两唐书等可公开访问版本。
2. 正史和权威整理文本，优先补公开链接、卷次、章节。
3. 权威研究，必须补作者、书名/论文名、出版社或期刊、页码；未补齐前只作“待补”，不支撑强判断。
4. 官方通识课程或视频，只做入门框架，不支撑争议性结论。
5. 野史、营销号、无出处二手文章，当前阶段不录入。

古籍链接只作为出处。界面默认展示白话释义和阅读提示，不能只展示文言原文。

## 覆盖策略

帝王谱系负责全覆盖，事件详情负责重点解释。

每位皇帝至少要有一个大事索引；如果一位皇帝在位期有多个核心大事件，就全部保留，不设置数量上限。不是每个皇帝都要膨胀成百科页，但每个皇帝必须能和他的在位大事建立联系。

事件页不再强行压缩到固定数量。凡是影响唐朝政治结构、制度变化、边疆格局、财政体系、社会秩序、政权兴亡的大事件，都可以逐步升级成完整事件页。

朝代内部仍按时期组织，例如初唐、盛唐、中唐、晚唐。时期是组织方式，不是限制事件数量的理由。

## 后续优先级

1. 把重点转折继续升级成完整事件页，例如贞观之治、灭高句丽、天宝政治、灵武即位、牛李党争、河陇恢复。
2. 把 `citations` 从“引用线索”升级为“已核验引用”：补原文、白话解释、卷章、页码。
3. 给每个重点事件补 `claims`，保证关键判断可追溯。
4. 按 `process` 规则继续扩写后续新增事件的经过节点。
