# 经过节点规则

## PROC-001 节点职责

- 状态：`active`
- 规则：`process` 是大事件内部的“小事件”或经过，必须说明事情如何推进。
- 每个节点：参与者、行动过程、具体影响，且能解释下一节点或阶段转折。

## PROC-002 长度与表达

- `description` 通常 45-120 个汉字；低于 35 字视为质量问题。
- 白话、具体、不过度展开；不得用“影响深远”“局势变化”等空泛句替代史实。
- 不重复 `summary` 或 `results`，重点写发生了什么。

## PROC-003 结构化字段

新增或重写节点应包含：

```js
{
  time: "时间",
  title: "节点标题",
  description: "页面主说明",
  participants: ["人物、政权、组织或群体"],
  action: "具体行动或变化",
  impact: "可观察的后续影响"
}
```

其中 `participants`、`action`、`impact` 必须非空；已有历史数据按批次补齐。

## PROC-004 节点数量

- 普通核心事件：至少 3 个有事实差异的节点。
- 统一战争、政权建立、王朝崩溃、重大改革：通常至少 5 个节点。
- 不得使用“背景—展开—影响”的统一模板替代事件特有过程。

## PROC-005 历史谨慎

- 因果必须避免单因果过度简化。
- 有争议的规模、动机和细节须降低断言强度并绑定来源。
- 后世概念不得无说明地倒灌为当时完整制度。

## PROC-006 学习案例按事件组织

- 状态：`active`
- 适用范围：新建或重写的核心事件详情、`learningCase`。
- 规则：学习案例先回答该事件独有的历史问题，再选择必要的论点、过程、证据、反误解和检索题；不得为满足字段数量套入统一叙事顺序。
- 内容要求：核心判断必须能被具体事实、可指认的史料或研究争议支撑；“影响深远”“促进交流”“局势变化”等不能单独充当解释。反误解只在确有常见简化说法时出现。
- 数据或代码影响：`learningCase` 为可选字段；其段落标题和数量按事件自定义，缺少有效内容的栏目不渲染。
- 审计方式：抽查时确认每个已标记案例至少有一个可核对的材料锚点，并删除与事件无关的泛化段落；自动校验不以凑字段代替人工史实核查。
- 例外和风险：纯时间定位或材料不足的事件可不设学习案例，保留普通详情并明确材料限制；不得为追求“有卡片”虚构动机、数字或争议。
- 生效版本：`2026.08.31`
